### v1.1（2026-09-15）：并行事项 + 截止日期

- 「下一步行动」（单字段）升级为「并行事项」列表：每项目可同时挂多条推进线，每条 = 一句话 + 可选截止日期 + 完成勾选
- 旧数据自动迁移：v1 的 `nextStep` 打开应用时自动转为第一条事项，零操作
- 分工明确：并行事项 = 我方在推的事；等待事项 = 等别人的事（外部依赖）
- 逾期/截止派生状态：事项逾期或当天截止 → 全景卡片橙色左边条 + 逾期天数；截止前 3 天内显示倒计时
- 焦点选择：全景卡片自动展示最早截止的未完成事项（无截止日期则显示第一条），并标注「另有 N 件」
- 今日建议优先级重排：逾期/今天截止事项 > 超时催办 > 2 天内截止 > 卡住 > 高优先 > 被遗忘；每项目至多 2 条（仅逾期可占 2 条）
- 周回顾新增「逾期与临近截止（7 天内）」段落
- 日期计算修正：等待天数与截止天数统一按当日零点计算，消除时段偏移导致的 ±1 天误差

### v1（2026-09-15）：首次交付

初始四视图（全景/今日/等待/回顾）、状态循环切换、等待超时与 N 天未动派生状态、转交、导入导出。

## 1. 背景与目标

用户为科研机构首席科学家，并行推进数十个项目。核心痛点：

1. 项目状态记不清（记不清每个项目进展到哪、卡在哪）
2. 待办/跟进遗漏（事情太多导致漏掉跟进、错过节点）
3. 优先级混乱（不知道当下最该推进哪件事）
4. 等待事项难追踪（记不清哪个项目在等谁回复，该催谁）

目标：一个轻量的、纯本地的手机端工具——一屏看清所有项目状态，10 秒内完成一次状态更新，自动找出"该催的"和"被遗忘的"。

## 2. 硬约束

- Android 手机（可正常安装应用/保存文件的普通安卓机）
- 项目数据涉密：数据不得离开设备，禁止任何云端同步与账号体系
- 个人使用为主，偶尔需把某条待办转交他人（助理/对接人）
- 排斥重型协作工具（Worktile 级）

## 3. 市场调研结论

调研覆盖 30+ 款产品（国产轻量应用、国际本地优先应用、可私有部署开源方案），结论：无一同时满足"纯本地存储 + 轻量开箱 + 几十个项目全景 + 等待事项追踪"四个条件。国产应用均为云端架构；Tasks.org 等纯本地应用只是任务清单；Obsidian 可拼装但移动端体验差、配置重；Vikunja 等私有部署方案需要内网服务器与运维。故选择自建。

## 4. 方案选型与演进路线

自建单文件网页应用（本地 HTML 文件，PWA 增强就绪），三阶段演进：

| 阶段 | 形态 | 说明 |
|---|---|---|
| v1（本次交付） | 单 HTML 文件 | 拷入手机 → Chrome 打开 → 菜单中"添加到主屏幕"生成快捷方式。数据存本机 localStorage，零网络请求 |
| v1.1（可选） | 内网静态服务 | 若单位内网可提供静态文件服务，以 https 部署获得完整 PWA 体验（可安装、离线缓存） |
| v2（按需） | Capacitor 打包 APK | 侧载安装，获得系统级定时提醒（本地闹钟，无需推送服务器）与独立应用私有存储。同一套代码，数据一键迁移，代码零重写 |

不直接写原生 APP 的理由：开发周期长数倍、每次改版需重新安装，而 v1 的需求 PWA 形态全覆盖；Capacitor 保留了升级通道，何时升级由用户决定。

## 5. 数据模型

**项目 Project**：

- `id`、`名称`（唯一必填项）
- `状态`：推进中 / 等待中 / 卡住 / 暂停 / 完成
- `下一步行动`：一句话
- `优先级`：高 / 中 / 低（默认中）
- `等待事项 WaitingItem[]`：{在等谁, 等什么, 开始等待日期, 期望天数（默认 7）, 已催次数, 最近催办日期}
- `日志 Log[]`：{日期, 一句话文本}（可选，用于回顾）
- `createdAt` / `updatedAt`（自动维护）

**派生状态**（自动计算，用户不需维护）：

- **等待超时**：存在等待事项，已等天数 > 期望天数 → 首屏橙色高亮（"该催了"）
- **N 天未动**：updatedAt 距今 > 阈值（默认 14 天，可在设置中调整）→ 首屏标记
- **卡住**：状态 = 卡住 → 红色，全景置顶

## 6. 界面设计（四视图 + 底部导航）

1. **全景（首屏）**：项目卡片流，自动排序（卡住 > 等待超时 > N天未动 > 按优先级与最近更新）；顶部筛选标签（卡住 / 等待超时 / 未动，带数量）；每卡片显示：名称、状态徽标、下一步或卡点、最后更新时间。点状态徽标循环切换状态（不打字）。
2. **今日**：自动汇总 ≤5 条——今天最该动的项目（超时等待优先、其次高优先级与久未动项目）及其下一步行动；支持勾选完成下一步。
3. **等待**：全部等待事项按"已等天数"倒序；每条显示"等谁 · 等什么 · 已等 N 天"；一键"已催"（记录催办时间）或"已回"（关闭该等待事项）。
4. **回顾**：自动汇总本周动态（新项目、状态变化、完成事项、各项目最近进展）生成纯文本，一键复制作为周报雏形。

**设置面板**（全景页右上角齿轮进入）：未动阈值天数、等待默认期望天数、导出/导入数据、清空数据（二次确认）。

## 7. 交互规则

- 常用操作 ≤ 3 次点击；改状态 = 点徽标循环切换，无需打字
- 新建项目必填仅"名称"，其余留空后补
- 新建等待事项：一句话"在等谁 · 等什么"，期望天数默认 7
- **转交**：任意项目/待办可点"转交"，生成格式化文本并复制到剪贴板，粘贴到微信即可发送
- 删除需二次确认；完成的项目归档显示，不物理删除

## 8. 数据安全

- 存储仅用 localStorage：本机、单文件、无网络、无账号；数据量为 KB 级
- 一键导出 JSON 文件（文件名含日期）、一键导入（导入前确认覆盖或合并）
- 超过 30 天未导出 → 回顾页温和提醒
- 已知风险与对策：浏览器清除站点数据会连带清除 localStorage（file:// 页面风险较低但不为零）——对策为培养导出习惯 + v2 APK 使用应用私有存储彻底规避
- 建议实践：导出文件存放于单位内网或加密 U 盘

## 9. 技术架构

- 单 HTML 文件：零依赖、零构建、零网络请求（可用浏览器网络面板验证为空）
- 原生 JS + localStorage（同步读写、实现简单可靠，几十个项目数据量远低于限额）
- 模块划分：存储层 / 派生状态引擎 / 四视图渲染 / 剪贴板与导入导出
- 移动端优先布局，跟随系统深色模式

## 10. 明确不做（Non-goals）

- 多人协作、云同步、账号体系
- 甘特图、依赖关系图、工时统计
- 日历集成、邮件/IM 集成
- 系统级推送提醒（推迟到 v2 APK 阶段）

## 11. 验收标准

1. 单 HTML 文件在 Android Chrome 直接打开即可用，全程零网络请求
2. 录入 30 个项目后首屏滚动流畅
3. 状态更新 ≤ 3 次点击；新建等待事项 ≤ 10 秒
4. 全景排序规则：卡住 > 等待超时 > N天未动 > 其他（按优先级、更新时间）
5. 导出 → 清空 → 导入，数据往返无损
6. "转交"文本粘贴到微信显示正常（含项目名、事项、期限）

## 12. 实施步骤

1. 数据层 + 派生状态引擎
2. 全景视图 + 状态交互 + 设置面板
3. 等待视图 + 今日视图
4. 回顾视图 + 导出导入 + 转交
5. 移动视口与深色模式走查
6. 交付：HTML 文件 + 一页使用说明（放入手机、添加主屏、备份方法、升级路线）
